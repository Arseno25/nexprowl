## Overview

NexProwl v0.1.0 is the first public release: a fast, dependency-light, single
binary that runs a full reconnaissance pass — DNS, subdomain discovery, port
scanning, HTTP probing, TLS analysis, virtual host discovery, subdomain takeover
detection, and crawling — without chaining half a dozen separate tools.

Modules feed each other inside a single run: `dns` produces the IPs `ports` and
`vhost` scan, `sub` produces the hosts `http` probes and the CNAMEs `takeover`
inspects. Targets run in parallel, modules run sequentially per target, and each
module parallelizes internally with its own worker pool.

Every directory-mode scan is written to an immutable timestamped run, so
`nexprowl diff` can tell you what changed in an attack surface between Tuesday
and Friday.

The only direct dependency is [`pterm`](https://github.com/pterm/pterm) for the
terminal UI. Everything else is the Go standard library.

## Main features

**Eight modules**, selectable with `-m`:

| Module | What it does |
|---|---|
| `dns` | A/AAAA/MX/NS/TXT/CAA/SOA/SRV/PTR, SPF/DMARC, ASN ownership, wildcard detection, AXFR zone-transfer attempts |
| `sub` | Passive enumeration from keyless sources, optional keyed sources, TLS SAN harvesting, wordlist bruteforce, wildcard filtering |
| `ports` | Multi-host/IP TCP connect scan with service naming and banner grabbing |
| `http` | Port-aware HTTP/HTTPS probing, body and favicon hashes, response timing, technology/WAF/CDN detection |
| `vhost` | Virtual host discovery via Host-header and SNI fuzzing, filtered against a wildcard-noise size model |
| `tls` | Multi-endpoint certificate inspection: issuer, cipher, validity, expiry, hostname mismatch, SANs |
| `takeover` | Dangling-CNAME detection, verified by NXDOMAIN *and* unclaimed-page body markers so services that keep resolving are still caught |
| `crawl` | Bounded same-scope HTML/JS/robots/sitemap endpoint discovery |

**Output** in JSON, JSONL, CSV, Markdown, HTML, or plain text — picked from the
`-o` extension or forced with `-format`. Directory mode additionally writes a
summary CSV, an HTML report with a zoomable architecture map, a manifest, and
plain `subdomains.txt` / `urls.txt` / `hostports.txt` / `endpoints.txt` /
`ips.txt` asset lists.

**Run history and comparison.** Directory-mode scans land in an immutable
timestamped folder with `latest.txt` pointing at the newest. `nexprowl diff OLD
NEW` reports added and removed subdomains, URLs, host:port pairs, IPs,
endpoints, web state, TLS state, and takeover candidates, and exits `3` when
anything changed — which makes it a cron-friendly monitoring primitive.

**Pipelines.** Targets on STDIN, findings on stdout via `-emit
subdomains|urls|hostports|ips|endpoints|jsonl`, and `-silent` for one summary
line per target.

**Responsible-scanning controls.** `-rate`, `-jitter`, `-timeout`, `-max-hosts`,
`-include`/`-exclude` scope enforcement, and a `-stealth` preset that drops to
10 workers, 10 ops/sec, an 8-second timeout, and passive-only enumeration.

**Traffic controls.** `-proxy` (http/https/socks5/socks5h), `-doh` for
DNS-over-HTTPS, and `-r` for custom round-robin resolvers.

**Build metadata.** `nexprowl version` reports version, git commit, build date,
Go version, and OS/architecture, injected at link time.

## Installation

**Go install** (needs Go 1.24+):

```bash
go install github.com/Arseno25/nexprowl@latest
```

**Download a release** — grab the archive for your platform from the
[release page](https://github.com/Arseno25/nexprowl/releases/tag/v0.1.0),
extract, and put `nexprowl` on your `PATH`:

```bash
tar -xzf nexprowl_0.1.0_linux_amd64.tar.gz
sudo install -m 0755 nexprowl /usr/local/bin/
nexprowl version
```

**Build from source:**

```bash
git clone https://github.com/Arseno25/nexprowl.git
cd nexprowl
go build -trimpath -ldflags="-s -w" -o nexprowl .
```

**Docker:**

```bash
docker build -t nexprowl:0.1.0 .
docker run --rm -v "$PWD/results:/results" nexprowl:0.1.0 example.com
```

## Basic usage

```bash
# Everything, one target
nexprowl example.com

# Pick your modules
nexprowl example.com -m dns,sub,http,tls

# Batch, 10 concurrent targets, saved to results/
nexprowl -l targets.txt -T 10

# Low-noise preset
nexprowl -stealth example.com

# Machine-readable output
nexprowl example.com -o result.json -format json

# Pipeline in and out
echo example.com | nexprowl -silent -emit urls

# Compare two runs (exit 3 = something changed)
nexprowl diff results/<OLD> results/<NEW>
```

`nexprowl --help` is the authoritative flag reference.

## Known limitations

- **`-screenshot` needs an installed Chrome or Chromium.** NexProwl shells out
  to a system browser instead of bundling one. It does not work in the minimal
  Docker image.
- **`-race` builds need a C compiler.** Only relevant to contributors running
  the test suite locally; CI covers it.
- **No shell completions and no man page.** The CLI uses the standard library's
  `flag` package, which has no completion generator. Both are on the roadmap and
  would require a CLI framework change.
- **No Homebrew, Scoop, apt, or AUR package.** Templates exist under
  `packaging/` but nothing is published. Use `go install`, the release archives,
  or Docker.
- **No published container image.** The `Dockerfile` works; pushing to a
  registry is on the roadmap.
- **Keyed passive sources are opt-in** via `NEXPROWL_SECURITYTRAILS_KEY`,
  `NEXPROWL_VIRUSTOTAL_KEY`, and `NEXPROWL_SHODAN_KEY`. Without them, only the
  keyless sources run.
- **Port scanning is TCP connect only.** No SYN scan, no UDP, no OS
  fingerprinting — those need raw sockets and privileges NexProwl deliberately
  does not ask for.
- **Wildcard DNS filtering is heuristic.** It resolves random names and filters
  matching bruteforce hits; a target with per-name wildcard responses can still
  produce noise.

## Security and legal notice

**NexProwl is for authorized security testing only** — engagements with written
permission, bug bounty programs whose scope covers the target, and assets you
own.

Most modules send traffic to the target. Port scanning, virtual host fuzzing,
zone transfer attempts, crawling, and `-active` probes are all observable and
attributable to you. Running them against infrastructure you are not authorized
to test may be a criminal offence in your jurisdiction. **You are responsible for
how you use this tool.**

Note that certificate verification is intentionally disabled for scan traffic —
reporting on expired and mismatched certificates is what the `tls` module is
for. It is *not* disabled for `-webhook` delivery or DNS-over-HTTPS, which use
fully verified clients.

Scan output routinely contains sensitive information about the systems you
tested. It is written with default file permissions; store it accordingly.

To report a vulnerability **in NexProwl itself**, use
[private vulnerability reporting](https://github.com/Arseno25/nexprowl/security/advisories/new).
Never open a public issue for a security bug. See [SECURITY.md](../../SECURITY.md).

## Verifying your download

Download `checksums.txt` from the release page alongside your archive.

Linux / macOS:

```bash
sha256sum -c checksums.txt --ignore-missing
```

Windows PowerShell:

```powershell
(Get-FileHash .\nexprowl_0.1.0_windows_amd64.zip -Algorithm SHA256).Hash.ToLower()
Select-String -Path .\checksums.txt -Pattern 'windows_amd64'
```

The two values must match. If they do not, do not run the binary — re-download,
and if it still mismatches, report it.

After installing, confirm you have a real release build:

```bash
nexprowl version
```

Version, commit, and build date must show real values. If they read `dev`,
`none`, and `unknown`, you are running a locally compiled binary, not a release
artifact.

## Reporting bugs

Open a [bug report](https://github.com/Arseno25/nexprowl/issues/new/choose) with:

- `nexprowl version` output
- The exact command you ran, with real target names redacted
- What you expected, what happened, and the error output (`-no-color` helps)
- A reproduction against `example.com` or a local lab host if you can manage one

Questions rather than defects go to
[Discussions](https://github.com/Arseno25/nexprowl/discussions). Security
vulnerabilities go through [private reporting](https://github.com/Arseno25/nexprowl/security/advisories/new),
never a public issue.
